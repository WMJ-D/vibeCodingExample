## 一、目录结构

```
todo-app-hbuilderx/

├── uni.scss                   # 全局 SCSS 变量
│
├── store/
│   └── todo.js                # ⭐ 状态管理中心（reactive + localStorage）
│
├── components/                # 公共组件
│   ├── TabBar.vue             # 底部导航栏（首页 / 统计）
│   ├── SystemCapsule.vue      # 顶部胶囊按钮（装饰性）
│   └── Icon.vue               # SVG 图标组件（H5 用 SVG，非 H5 用 emoji 兜底）
│
└── pages/
    ├── calendar-home/         # 📅 首页：日历 + 待办列表
    ├── add-task/              # ➕ 新建任务表单
    └── task-stats/            # 📊 数据统计页面
```

### 关键文件说明

| 文件 | 职责 |
|------|------|
| `manifest.json` | 应用名称、appid、版本号、各平台权限配置 |
| `pages.json` | 注册三个页面路由，统一设置自定义导航栏 + 暗色背景 |
| `main.js` | Vue3 `createSSRApp` 入口，兼容 Vue2 条件编译 |
| `App.vue` | 应用启动时调用 `initStore()` 初始化本地存储；定义全局暗色样式 |

## 二、核心架构设计

### 2.1 状态管理

采用 **Vue3 `reactive` + `uni.setStorageSync`** 的轻量方案，未引入 Vuex/Pinia。

```js
// store/todo.js — 全局响应式状态
import { reactive } from 'vue'

export const state = reactive({
  tasks: [],               // 任务数组
  selectedDate: new Date().toISOString().slice(0, 10),  // 当前选中日期
  calendarMode: 'month'    // 日历模式：'month' | 'week'
})
```

**对外暴露的操作方法**：

| 方法 | 参数 | 返回值 | 说明 |
|------|------|--------|------|
| `addTask(task)` | 任务对象（title, date, time, tag, priority…） | 新任务对象 | 自动生成 ID，unshift 到数组头部 |
| `toggleTask(id)` | 任务 ID | void | 切换完成状态 |
| `deleteTask(id)` | 任务 ID | void | 从数组中移除 |
| `setSelectedDate(date)` | 日期字符串 'YYYY-MM-DD' | void | 更新选中日期 |
| `setCalendarMode(mode)` | `'month' \| 'week'` | void | 切换日历视图模式 |

---

### 2.2 数据模型

每条任务的数据结构如下：

```typescript
interface Task {
  id: number            // 时间戳生成（Date.now()）
  title: string         // 任务标题（必填）
  date: string          // 日期 'YYYY-MM-DD'
  time: string          // 开始时间 'HH:mm'
  endTime: string       // 结束时间 'HH:mm'（可选）
  tag: string           // 标签名：工作 / 生活 / 学习 / 健康 / 购物
  priority: string      // 优先级：'high' | 'medium' | 'low'
  completed: boolean    // 是否已完成
  reminder: boolean     // 是否开启提醒
}
```

### 2.4 持久化策略

```
首次启动 → 无本地数据 → 写入 7 条种子示例数据 → 同步到 Storage
后续启动 → 从 uni.getStorageSync('todo_app_tasks') 加载 → 恢复到 state.tasks
每次 CRUD → 自动调用 saveToStorage() → JSON 序列化写入 Storage
```

**Storage Key**：`todo_app_tasks`  
**种子数据**：包含 7 条覆盖各标签和优先级的示例任务，日期分布在当天及前后两天。

## 三、页面功能详解

### 3.1 日历首页 (`pages/calendar-home/calendar-home.vue`)

**页面职责**：以日历为核心入口，展示选中日期的待办任务列表。

#### 功能模块

| 区域 | 功能描述 |
|------|----------|
| **状态栏** | 左侧显示当前日期文本（如"6月 周五"），右侧放置 SystemCapsule 胶囊装饰 |
| **日历区域** | 月/周双视图切换；月份前后翻页导航；星期标题行；日期网格（月视图含上月空白填充） |
| **日期格子交互** | 今日高亮、选中态高亮、过去日期置灰；有任务的日期显示小圆点标记 |
| **待办列表** | 按「上午 / 下午」以 12:00 为界分组展示当日任务 |
| **任务卡片** | 复选框（点击切换完成）+ 标题 + 优先级色条 + 时间段 + 标签徽章；已完成态有视觉置灰效果 |
| **空状态** | 当天无任务时展示引导插图 + "点击右下角 + 添加任务" 提示 |
| **FAB 按钮** | 右下角浮动 "+" 按钮，点击跳转新建任务页 |
| **底部 Tab** | TabBar 组件，当前激活 "home" |

#### 核心计算属性

| 属性 | 说明 |
|------|------|
| `calendarDays` | 生成当月完整 6 行网格（42 格），含上月尾部空白填充、本月日期（带 isToday/isSelected/hasTask/isPast 标记）、下月头部填充 |
| `weekDays` | 以选中日期所在周一为起点，生成连续 7 天的周视图数据 |
| `groupedTasks` | 过滤选中日期的任务，按 `time < '12:00'` 分为 morning / afternoon 两组 |
| `taskCount` | 当日任务总数 |
| `monthLabel` | 当前显示月份文本（如"6月"） |
| `statusBarDate` | 状态栏日期格式化文本 |

#### 页面方法

| 方法 | 触发场景 | 说明 |
|------|----------|------|
| `prevMonth()` / `nextMonth()` | 点击月份导航箭头 | 修改 currentYear/currentMonth |
| `selectDay(day)` | 点击日期格子 | 更新 selectedDate |
| `handleToggle(id)` | 点击任务复选框 | 调用 store 的 toggleTask |
| `goAddTask()` | 点击 FAB 按钮 | `uni.navigateTo` 携带当前选中日期跳转新建页 |
| `getPriorityColor(priority)` | 卡片渲染 | 返回优先级对应颜色 |
| `getTagStyle(tag)` | 卡片渲染 | 返回标签对应的 color + background 内联样式 |

### 3.2 新建任务 (`pages/add-task/add-task.vue`)

**页面职责**：提供完整的任务创建表单。

#### 表单字段

| 字段 | UI 控件 | 默认值 | 校验规则 |
|------|---------|--------|----------|
| **标题** | `<input>` 文本框 | 空 | 必填，trim 后非空 |
| **日期** | ActionSheet 快捷选择 + 自定义 | 当天日期 | 支持「今天/明天/后天/自定义」四种方式 |
| **时间** | H5 原生 time input / 非 H5 弹窗输入 | `15:00` | 格式 HH:mm |
| **标签** | 单选 Chip 组 | `工作` | 五选一 |
| **优先级** | 单选列表（带色点） | `medium` | 高/中/低三选一 |
| **提醒** | Toggle Switch | `开启` | 开启后显示"提前 15 分钟提醒"提示文字 |

#### 交互细节

- **日期选择**：弹出 `uni.showActionSheet`，前三个选项为快捷日期，第四个触发平台适配选择器（H5 用 `<input type="date">`，非 H5 用 `uni.showModal` 手动输入）
- **时间选择**：同上，H5 用原生 `<input type="time">`，非 H5 用弹窗输入
- **保存流程**：校验标题 → 构建任务对象 → 调用 `addTask()` → Toast 提示成功 → `uni.navigateBack()` 返回首页

#### 页面生命周期

```
onLoad(options) → 从 URL 参数读取 date（从首页 FAB 携带）→ 回退到今天 → updateDateLabel()
```

### 3.3 数据统计 (`pages/task-stats/task-stats.vue`)

**页面职责**：可视化展示任务完成情况的多维度统计。

#### 四大统计卡片

##### ① 完成率环形图

| 属性 | 说明 |
|------|------|
| **图表类型** | SVG `<circle>` + `stroke-dasharray`（H5）/ `conic-gradient`（非 H5 兜底） |
| **中心数值** | 总完成率百分比（`completed / total * 100`） |
| **右侧统计** | 已完成任务数（绿色）+ 未完成任务数（灰色） |

##### ② 柱状趋势图

| 属性 | 说明 |
|------|------|
| **X 轴** | 最近 7 天（周一 ~ 周日中文标签） |
| **Y 轴** | 每天已完成的任务数（相对高度百分比） |
| **今日高亮** | 当天的柱子有特殊高亮样式 |
| **切换** | 支持「周 / 月」视图切换（月视图预留接口） |

##### ③ 分类完成情况

| 属性 | 说明 |
|------|------|
| **展示形式** | 每个标签一行，左侧标签名 + 右侧"完成数/总数"，下方进度条 |
| **进度条宽度** | 该标签完成率百分比 |
| **进度条颜色** | 使用标签自身的主题色 |

##### ④ 归档入口

- 文字链接："查看已归档任务 ›"
- 当前为预留功能位，未实现具体逻辑

#### 计算属性 `stats` 结构

```js
{
  total: number,        // 总任务数
  completed: number,    // 已完成数
  pending: number,      // 未完成数
  rate: number,         // 完成率 0-100
  byTag: {              // 按标签分组
    [tagName]: { total, done, rate, color, bg }
  },
  weekData: [           // 最近 7 天数据
    { count, label, isToday }
  ],
  maxWeek: number       // 用于柱状图归一化的最大值
}
```

## 七、设计亮点与优化建议

### ✅ 设计亮点

1. **轻量状态管理**
   - 无 Vuex/Pinia 依赖，一个 `reactive` 对象 + 几个导出函数即搞定全局状态
   - 代码量小、易理解、适合中小型应用

2. **渐进式体验**
   - 首次启动自动注入 7 条示例数据，用户打开即可看到完整效果
   - 避免了空白应用的"冷启动尴尬"

3. **时间维度组织**
   - 以日历为核心入口，而非传统列表式 Todo
   - 任务按日期聚合、按时段（上午/下午）分组，更符合日常使用直觉

4. **统一的暗色 UI 体系**
   - 全局色彩系统一致：背景 `#1A1A1E`、卡片 `#222226`、文字 `#F5F5F7`
   - 标签色彩兼顾辨识度与美观度

5. **跨端降级策略**
   - H5 端享受完整的 SVG 图表和原生 input 体验
   - 小程序/App 端通过 emoji 和弹窗确保功能可用

### 💡 可选优化方向

| 方向 | 建议 |
|------|------|
| **编辑任务** | 当前仅支持新增/完成/删除，可增加任务编辑页（复用 add-task 表单） |
| **归档功能** | 统计页已有入口，可实现将早期已完成任务归档归档、减少活跃列表长度 |
| **搜索/筛选** | 增加按标签、优先级、日期范围的全局筛选能力 |
| **拖拽排序** | 支持任务卡片长按拖拽调整顺序 |
| **云同步** | 接入 uniCloud 或自有后端，实现多设备数据同步 |
| **推送提醒** | 利用 `reminder` 字段 + uni 推送能力实现真正的定时通知 |
| **Pinia 迁移** | 若功能持续扩展，可考虑迁移至 Pinia 以获得更好的 DevTools 支持和模块化 |
| **单元测试** | 为 Store 操作函数和计算属性补充 Jest/Vitest 测试用例 |
